# 🔰 Обзор проекта: ANSYS Automation

Этот документ содержит ключевую информацию о проекте для эффективного взаимодействия и дальнейшей разработки.

## 📝 Краткое описание

Проект представляет собой **data-driven** систему для автоматизации настройки конечно-элементных моделей опорных конструкций в **ANSYS Mechanical**. Он берет на себя рутинные задачи по настройке сетки, контактов, нагрузок, граничных условий и результатов расчета, основываясь на данных из конфигурационных JSON-файлов.

**Ключевая архитектурная особенность:** Логика и параметры вынесены из кода во внешние конфигурационные файлы, что позволяет легко адаптировать и расширять систему под новые типы конструкций без изменения основного Python-кода.

## 🚀 План развития проекта

Подробная дорожная карта развития проекта, включая текущие задачи по отладке и реализации нового функционала, находится в файле [ROADMAP.md](../ROADMAP.md).

## 🏃‍♀️ Запуск и использование

Код предназначен для выполнения непосредственно в скриптовой консоли ANSYS Mechanical.

1.  **Подготовка модели:**
    *   В SpaceClaim или другом редакторе подготовить геометрию.
    *   Присвоить телам и группам граней осмысленные `Named Selections` (например, `fixed_support_ns`, `bolts_group_ns`).
    *   Имя модели должно соответствовать шаблону, который используется для определения типа конструкции (например, `151-02-F2`).

2.  **Запуск скрипта:**
    *   Открыть ANSYS Mechanical с подготовленной моделью.
    *   Открыть консоль `Scripting`.
    *   Выполнить следующий код, указав корректный путь к проекту:

    ```python
    import sys
    # Укажите полный путь к папке AnsysAutomation
    sys.path.append(r'C:\Users\user\source\repos\ANSYS Automation\AnsysAutomation')
    from main import run_automated_analysis

    # Запуск основного процесса автоматизации
    run_automated_analysis()
    ```

## 🛠️ Ключевые команды и соглашения по разработке

### Среда исполнения
- **Интерпретатор:** `IronPython 2.7.4` в составе ANSYS Mechanical.
- **Ограничения:**
    - Код должен соответствовать синтаксису **Python 2.7**.
    - Запрещено использовать библиотеки с C-расширениями (`NumPy`, `Pandas` и т.д.). Допускаются только "чистые" (pure Python) библиотеки.
    - Установка пакетов (`pip`) невозможна. Зависимости добавляются в проект вручную.

### Структура проекта
- **`main.py`**: Главная точка входа, оркестрирующая весь процесс.
- **`config/`**: Модули для работы с конфигурацией.
- **`config_files/`**: **"База данных" проекта**. Содержит JSON-файлы с настройками сетки, нагрузок, сценариев анализа и т.д.
- **`core/`**: Ключевая логика, не связанная напрямую с настройкой Ansys (определение типа конструкции, управление выполнением).
- **`managers/`**: Классы-менеджеры, отвечающие за конкретный аспект настройки модели (`MeshManager`, `ContactManager` и т.д.).
- **`utils/`**: Вспомогательные утилиты (парсеры, валидаторы).

### Тестирование
- Тесты должны размещаться в папке `tests/` в корне проекта.
- Вместо `pytest` (который несовместим) следует использовать встроенный модуль `unittest`.

### Контроль версий (Git)
- **Рабочий процесс:**
    1.  AI-агент вносит изменения в код.
    2.  AI-агент подготавливает коммит (`git commit -m "..."`) с детальным описанием.
    3.  **Пользователь** проверяет коммит и выполняет отправку на удаленный сервер (`git push`).
- **Коммиты:** Сообщения коммитов должны быть на русском языке, в императивной форме (например, "Добавить логирование в модуль ...", "Исправить ошибку ...").
